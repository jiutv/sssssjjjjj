# 直播三种起播方式测试用例

适用版本：MBox v1.4.1（versionCode 48，nightly-99）
测试对象：直播模块新增的直连、`video://` 嗅探、`webview://` 网页起播
包名：`com.github.tvbox.osc`

---

## 1. 测试范围

| 范围 | 说明 |
|---|---|
| 直连起播 | HTTP / HTTPS / RTMP / M3U8 / MP4 直接交原生播放器，沿用原解码配置与错误处理 |
| `video://` 嗅探 | 隐藏 WebView 嗅探 m3u8 / MP4 / MPD / FLV / RTMP，命中后交原生播放器 |
| `webview://` 网页 | WebLiveActivity 承载 WebView，网页播放器自行拉流，支持全屏、横竖屏、返回键、失败重试 |
| 关联改动 | TXT 订阅协议白名单、统一起播入口、投屏地址、解码切换 |
| 不在范围 | 订阅管理页、EPG、收藏/历史、点播播放、首页/详情（仅做回归验证） |

## 2. 测试环境

- 设备：Android 9 及以上真机 1 台（优先使用用户反馈机型 Samsung SM-N9860 / Android 13），另加 1 台低端机验证解码兼容
- 网络：Wi-Fi（可访问公网） + 4G；需具备断网、限速能力
- 播放器设置：分别覆盖 系统播放器 / IJK / Exo（Media3） 三种解码
- 抓包工具：Charles / mitmproxy（HTTPS 需配合证书），或 logcat
- 观测关键字：logcat 过滤 `LiveSniffer`

### 4.1 直连起播

| 编号 | 优先级 | 前置条件 | 操作步骤 | 预期结果 |
|---|---|---|---|---|
| TC-D-01 | P0 | 订阅含「直连HLS」 | 进入直播 → 点击「直连HLS」 | 原播放器正常出画；画面、EPG、台标信息与改动前一致 |

## 5. 观测与判定方法

1. **界面**：Toast 文案、播放器是否出画、重试入口是否出现、全屏是否退出。
2. **logcat**：
   ```
   adb logcat | grep -E "LiveSniffer|AndroidRuntime|WebView"
   ```
   关注 `LiveSniffer filter:` / `LiveSniffer ad:` 与崩溃堆栈。
3. **抓包**：确认嗅探媒体请求携带的 UA/Referer/Cookie 来自网页本身；确认无硬编码请求头。
4. **投屏**：接收端日志中的 URL 应为真实流地址。

## 6. 通过标准

- P0 用例 100% 通过；P1 通过率 ≥ 95%；P2 无阻塞性问题。
- 三种协议均可起播；失败场景全部按原「换源 → 换台」规则收敛，无卡死、无崩溃。
- 非直播功能回归无新增问题。

## 7. 已知限制（非缺陷，测试时按此判定）

1. 协议前缀区分大小写（`video://`、`webview://` 必须小写）。
2. `webview://` 返回后自动重开是已确认的产品行为，因此返回键无法直接退出网页播放；连续快速返回 3 次会停止自动重开。
3. 网页能否播放取决于目标站点自身（防盗链、DRM、禁止嵌入、WebView 内核能力），嗅探与网页播放不注入任何破解脚本。
4. WebView 通常不会发起 RTMP 请求，嗅探实际主要命中 m3u8 / MP4 / MPD / FLV。
5. DASH 播放依赖当前播放器能力；设备不支持时按原规则失败换源。
